# GoA2 — Guards of Atlantis II (digital, for friends)

A **digital multiplayer** version of the
Guards of Atlantis II board game (lobby → teams → hero draft → board). Personal use.

Deployed to GitHub Pages: **https://7wjfh4pg2y-dev.github.io/goa2/**

## Architecture
- **`src/routes/+page.svelte`** — THE whole flow (big file ~900 lines). Modes:
  `landing → choose → admin/adminhub → menu → create/join → lobby → draft → game`.
  - `landing`: big crest splash, morphs (width+translateY) into `choose`. No SFX (removed).
  - Role gate: `src/lib/role.ts` (admin password `[the admin password]`, SHA-256 soft gate).
  - Identity/resume (`src/lib/identity.ts`): `clientId` is **per tab** (sessionStorage) so two tabs = two players. Each tab keeps an expiring (30 min) resume ticket `localStorage['goa2-active:<id>']` and holds a Web Lock `goa2-id-<id>`; a reopened tab adopts a ticket's id only if no open tab holds its lock. `claimIdentity()` runs on mount, then auto-rejoins. Don't go back to a shared localStorage id — it merged tabs into one player and resurrected stale games.
  - Begin flow: **tie-breaker coin flip → host `buildDraft()` → everyone enters draft → host "Start game" → board (placeholder)**.
- **`src/lib/match.ts`** — shared match state engine over one Supabase channel per room.
  - Sync model: **full-snapshot last-write-wins by `rev`** (ties by `updatedAt`). `update()` bumps rev + broadcasts (throttled/coalesced ~140ms). Presence `track()` also throttled (~320ms) — Supabase rate-limits per channel; flooding wedges the socket.
  - Auto-reconnect **watchdog** rebuilds the channel with backoff if it stays down, plus a **join deadline** (8s without SUBSCRIBED → rebuild) so a cold first join never sits on "connecting". Rebuilds go through `dropChannel()` (waits ≤3s for the leave, then purges the old channel from the client — `supabase.channel(topic)` otherwise hands back the dying one); status callbacks are per channel; `supabase.ts` patches realtime's `_remove` to compare by identity (it filters by topic).
  - Players live in **presence** (id, name, colour, ready, seat). Seat `< 0` = spectator/unseated. `teamForSeat`: first half = orange, second = blue.
  - **Draft** state lives in shared match state (`draft: DraftState | null`), so it persists across disconnects. `buildDraft / draftAdvance / draftSetPick / draftComplete / draftBlocked / teamRosters`. Systems: `all-pick | all-random | single-draft | pick-ban`. `DRAFT_TURN_MS = 45000`. `lastAction` drives the announcement toast.
  - **Host hand-over** (`nextHost` + `checkHost` in match.ts, tested): only the host applies card actions / runs the watchdogs, so if the host is missing from presence for `HOST_GRACE_MS` (10 s — rides out a refresh/reconnect) the next SEATED player after the host's seat (wrapping; else first spectator by id) claims `host` via `act` (logged "is now the host (X disconnected)"). Every client computes the same successor; only that one acts. Skipped while we're offline ourselves or the room is `closed`. The public room listing follows automatically (+page re-announces for whoever `iAmHost`).
  - Coin flips (join team + start tie-breaker) use a broadcast-instruction pattern so each client applies its own presence — avoids LWW map clobber.
- **`src/lib/HeroDraft.svelte`** — the live draft screen (cinematic full-splash layout). Strict turn ownership; host watchdog auto-picks on timeout / ~8s after the active player drops; all-pick self-heal for concurrent locks.
- **`src/lib/lobby.ts`** — public room directory via a presence channel (open-games list).
- **`src/lib/heroes.ts`** — 32 heroes (id, name, title, stars, pack, traits, stats) + art resolvers: `heroAvatar` (`images/avatars`), `heroSplash` (`images/avatars_full`), `heroLogo` (`images/logos`), `statIcon`/`traitIcon`/`starIcon` (`images/hero_icons`). `tokens` trait has no icon (falls back to a ◈ glyph).
- **`src/lib/maps.ts`** — map registry. **Bundled maps come first and are the default** (every host plays the same board); an editor/saved copy with the same name only appears if it differs, as "(edited)". `src/lib/maps/forgotten_island.json` is the official board (battleZone = 4 melee/1 ranged/1 heavy per team).
- **`src/lib/transitions.ts`** — `reveal` (fade+translate+scale+blur) used between steps.
- **`OLD/`** — the archived previous build; **not compiled/served**. Mine it for assets/logic (e.g. `states.ts` heroes, `BoardCanvas.svelte`, draft algorithms).

- Glass cards `rgba(12,18,32,.46)` + blur + soft border. Highlight gradient token `--hl: linear-gradient(120deg,#ef7d22,#2f7fe6)`.

## Gotchas
- Svelte 5 legacy: `$:` only tracks vars referenced **directly** — not vars read inside a called function. Avoid reactive cycles (compute-on-demand functions instead of reactive vars when a value both reads and writes another).
- **Desktop/tablet = one UI scale** (`src/lib/layout.ts`, tested): everything is designed at 1440×900 and scaled by `s = clamp(min(w/1440, h/900), .7, 2.2)`. GameView puts `layoutVars()` (`--uis --ds --dx --dh --db`) on `.gamewrap` (not on phones); CardLayer computes the same. HUD, player panel, modals, pietool, pvbar, big-card view use `zoom: var(--uis)` — zoom also scales an element's OWN insets, so real-px values (dash height, JS anchor coords) are divided by `--uis`. Tray/pv card use `calc(px * var(--uis))`. The dash is one fixed `DASH_W`×`DASH_H` design scaled via `--ds`; if it can't fit beside the HUD (portrait iPad) it spans the full width and both panels stop above it (`.dashfull`, `.withdash`). Every dash element has a reserved slot so nothing shifts. DeckView scales itself (cap 2.2). Root font-size is pinned to 16px.
- **Card faces are painted once and shared** (`src/lib/cards/render.ts`): `cardMaster(hero, card, extra, showNumbers)` paints a full-res 1192×1664 master once (kept as an uncompressed ImageBitmap, LRU of 32). `Card.svelte` is a `<canvas class="cardface">` that copies the master at its on-screen size × DPR × 2 (capped at full res; ResizeObserver + window resize redraw) — pixel-identical to the original on DPR ≥ 2, ~92% edge sharpness on DPR 1. Style card faces with `:global(.cardface)`. Measured dead ends (don't repeat): a canvas painted per Card on every mount (deck open 17 s on a phone-speed CPU); encoding faces to webp/png blobs for `<img>` (lossy webp looks softer; PNG/lossless encode is 0.5 s+/card and runs on Safari's main thread → 30 s+ to load); full-res canvases per Card (slow to composite/filter). The matchup splash prewarms your whole deck (`prewarm`, starting hand first, with a progress line) and downloads everyone's card art (`preloadArt`). The painter preloads only frame parts; token/rune/marker/tie-breaker/life art is `::emoji::`-only and loads on demand (`loadImages`). No `{#key}` around a Card — it swaps faces itself without a blank frame.
- **CSS:** `app.postcss` keeps only `@tailwind base` (preflight + Flowbite form resets the look depends on). The app uses NO Tailwind utility classes — everything is scoped Svelte CSS. Don't re-add the components/utilities layers or a safelist (that was 439 KB of CSS; now 13 KB).
- **Don't lazy-load GameView with a plain dynamic `import()`:** tried — with the preview routes importing it statically, the bundler's chunk split made modules evaluate out of order and the game screen crashed (`Cannot read properties of null (reading '$')`). Reverted. If retried, verify the deploy build (move the gitignored `preview-*` routes out) AND a live game.
- adapter-static: the game placeholder was once a catch-all `{:else}` and leaked onto other modes — scope each mode explicitly.
- Screenshot harness pattern (only when needed): build, serve `build/` with a tiny node http server that strips the `/goa2` base and falls back to `<route>.html`, launch Chromium at `executablePath:'/opt/pw-browsers/chromium'`, import playwright by absolute path from `node_modules`. Delete any `preview-*` route after.
