# GoA2 — Guards of Atlantis II (digital, for friends)

A **digital multiplayer** version of the
Guards of Atlantis II board game (lobby → teams → hero draft → board). Personal use.

Deployed to GitHub Pages: **https://7wjfh4pg2y-dev.github.io/goa2/**

## Architecture
- **`src/routes/+page.svelte`** — THE whole flow (big file ~1100 lines). Modes:
  `landing → choose → admin/adminhub → menu → create/join → lobby → draft → game`.
  - `landing`: the crest (large, left; centred on phones) over the live island, with an orange→blue Enter; the crest and the step stage persist, so the crest morphs into `choose`. No tagline, no SFX.
  - Role gate: `src/lib/role.ts` (admin password `[the admin password]`, SHA-256 soft gate).
  - Identity/resume (`src/lib/identity.ts`): `clientId` is **per tab** (sessionStorage) so two tabs = two players. Each tab keeps an expiring (30 min) resume ticket `localStorage['goa2-active:<id>']` and holds a Web Lock `goa2-id-<id>`; a reopened tab adopts a ticket's id only if no open tab holds its lock. `claimIdentity()` runs on mount, then auto-rejoins. Don't go back to a shared localStorage id — it merged tabs into one player and resurrected stale games.
  - Begin flow: **tie-breaker coin flip → host `buildDraft()` → everyone enters draft → host "Start game" → board (`GameView`)**.
- **`src/lib/match.ts`** — shared match state engine over one Supabase channel per room.
  - Sync model: **full-snapshot last-write-wins by `rev`** (ties by `updatedAt`). `update()` bumps rev + broadcasts (throttled/coalesced ~140ms). Presence `track()` also throttled (~320ms) — Supabase rate-limits per channel; flooding wedges the socket.
  - Auto-reconnect **watchdog** rebuilds the channel with backoff if it stays down, plus a **join deadline** (8s without SUBSCRIBED → rebuild) so a cold first join never sits on "connecting". Rebuilds go through `dropChannel()` (waits ≤3s for the leave, then purges the old channel from the client — `supabase.channel(topic)` otherwise hands back the dying one); status callbacks are per channel; `supabase.ts` patches realtime's `_remove` to compare by identity (it filters by topic).
  - Players live in **presence** (id, name, colour, ready, seat). Seat `< 0` = spectator/unseated. `teamForSeat`: first half = orange, second = blue.
  - **Draft** state lives in shared match state (`draft: DraftState | null`), so it persists across disconnects. `buildDraft / draftAdvance / draftSetPick / draftComplete / draftBlocked / teamRosters`. Systems: `all-pick | all-random | single-draft | pick-ban`. `DRAFT_TURN_MS = 80000` (1:20, then a 10 s red grace). `lastAction` drives the announcement toast.
  - **Host role is sticky** (tested): every host change bumps `hostEpoch`, and `applyRemote` never lets a snapshot with an older epoch move `host` back (a stale/concurrent update used to drag it around); undo never touches host. The room's `creator` takes the role back ~4 s after they're present again (`is the host again`). Realtime heartbeats run in a Web Worker (`worker: true` in supabase.ts) so throttled background tabs stay connected (they used to vanish from presence → host hand-over). There used to be a SECOND, instant smallest-id hand-over in +page.svelte — removed; don't re-add one. The reveal countdown runs on `session.hostNow()` (host clock estimated from the host's own snapshots), since `revealAt` is host time and device clocks drift.
  - **Host hand-over** (`nextHost` + `checkHost` in match.ts, tested): only the host applies card actions / runs the watchdogs, so if the host is missing from presence for `HOST_GRACE_MS` (15 s — rides out a refresh/reconnect) the next SEATED player after the host's seat (wrapping; else first spectator by id) claims `host` via `act` (logged "is now the host (X disconnected)"). Every client computes the same successor; only that one acts. Skipped while we're offline ourselves or the room is `closed`. The public room listing follows automatically (+page re-announces for whoever `iAmHost`).
  - Coin flips (join team + start tie-breaker) use a broadcast-instruction pattern so each client applies its own presence — avoids LWW map clobber.
- **`src/lib/HeroDraft.svelte`** — the live draft screen (cinematic full-splash layout). Strict turn ownership; host watchdog auto-picks on timeout / ~8s after the active player drops; all-pick self-heal for concurrent locks.
- **`src/lib/lobby.ts`** — public room directory via a presence channel (open-games list).
- **`src/lib/heroes.ts`** — 32 heroes (id, name, title, stars, pack, traits, stats) + art resolvers: `heroAvatar` (`images/avatars`), `heroSplash` (`images/avatars_full`), `heroLogo` (`images/logos/*.webp` — the hero symbols, 400 px, made from the user's high-resolution originals in `references/Icons/`; on every card back, the deck button, hero select and the matchup), `statIcon`/`traitIcon`/`starIcon` (`images/hero_icons`). `tokens` trait has no icon (falls back to a ◈ glyph). `splashFace(id)` = where the face sits in the BIG painting (`HERO_SPLASH_FACE`, found by matching each avatar inside its splash: the avatars are a 59% crop of the splashes, Tigerclaw's mirrored) — use `heroSplash` + `splashFace` whenever art is shown large; the small avatar art goes soft when enlarged (the user noticed at once).
- **`src/lib/maps.ts`** — map registry. **Bundled maps come first and are the default** (every host plays the same board); an editor/saved copy with the same name only appears if it differs, as "(edited)". `src/lib/maps/forgotten_island.json` is the official board (battleZone = 4 melee/1 ranged/1 heavy per team).
- **`src/lib/transitions.ts`** — `reveal` (fade+translate+scale+blur) used between steps.
- **`OLD/`** — the archived previous build; **not compiled/served**. Mine it for assets/logic (e.g. `states.ts` heroes, `BoardCanvas.svelte`, draft algorithms).

## Game recorder (quiet — no UI anywhere)
- `src/lib/recorder.ts` (tested): GameView runs `createRecorder(room, clientId).tick($ms)`; every browser keeps a full localStorage journal (`goa2-rec:<room>-<gameId>`; `$ms.gameId` is set by the host when the draft starts — `startFlip` is cleared by then, which is why the first recorded game has a "-0" id): players/heroes, draft, one snapshot per turn (level, coins, card played, Life, waves, lane), the WHOLE log (the shared one is capped at LOG_CAP), and the final state. A **full game** = seen from round 1 turn 1, won (`wonBy`), ≥2 different people seated — anything else is a test run (never sent; stale journals pruned after 3 days by `sweepJournals` on app start, which also retries failed uploads). On the win, the host inserts the row into Supabase table **`goa2_games`** (others retry after 15 s; the shared id makes duplicates fail harmlessly). The table is insert-only for the anon key (RLS, no select policy) — read it in the Supabase dashboard. The recorder is fail-safe (browser only, every error swallowed). **Structured events** (`Journal.ev`, tested): a hero defeat per `lastDefeat` news id (killer, fallen, assists, coins, lives, round/turn) and a minion defeat whenever a minion leaves the board in the same change that pays a player its 2 / 4 coins — read off the STATE each tick (`track`, with `mark` = what it saw last, saved with the journal so a reload carries on), never parsed out of the log's prose; the host's Undo is followed (an undone defeat comes off the list), and an undone WIN reopens the journal. Players carry `team` + `color` too. **Battle report:** `src/lib/gamestats.ts` `statsFromJournal(journal)` (tested) → `GameStatsData` for `GameStats.svelte`; GameView passes it to `VictorySplash` as `stats` (`$: gameStats`, cached per journal). It returns null — no report, never half the numbers — when the journal was not there from turn 1, misses a whole turn, or predates the events. Exact: rounds, level, K/D/A, falls, tide (a throne push ends on the throne), coins earned = coins held + every level's cost (level L→L+1 costs L; manual − adjustments net off). Minions per player are exact on the host and whenever each change arrived as its own snapshot (greedy split if two were merged: a heavy first when the gain is ≥4). Minutes = this browser's clock from the first turn to the win. Test games driven by scripts must block `**/rest/v1/goa2_games*` or they land in the real table.

## Gotchas
- Svelte 5 legacy: `$:` only tracks vars referenced **directly** — not vars read inside a called function. Avoid reactive cycles (compute-on-demand functions instead of reactive vars when a value both reads and writes another).
- **Desktop/tablet = one UI scale** (`src/lib/layout.ts`, tested): everything is designed at 1440×900 and scaled by `s = clamp(min(w/1440, h/900), .5, 2.2)`; the layout contract is under "In-game UI 2.0". GameView puts `layoutVars()` (`--uis`, …) on `.gamewrap` (not on phones); CardLayer computes the same (`dashVars`). The two HUD layers, the card view, the examine overlay and the victory screen use `zoom: var(--uis)` — zoom also scales an element's OWN insets, and everything inside a zoomed layer is in design px, so real-px values (JS anchor coords such as the piece toolbar's) are divided by the scale. DeckView scales itself (cap 2.2). Root font-size is pinned to 16px. (`--ds --dx --dh --db` are only read by the phone's card preview now.)
- **Card faces are painted once and shared** (`src/lib/cards/render.ts`): `cardMaster(hero, card, extra, showNumbers)` paints a full-res 1192×1664 master once (kept as an uncompressed ImageBitmap, LRU of 32). `Card.svelte` is a `<canvas class="cardface">` that copies the master at its on-screen size × DPR × 2 (capped at full res; ResizeObserver + window resize redraw) — pixel-identical to the original on DPR ≥ 2, ~92% edge sharpness on DPR 1. Style card faces with `:global(.cardface)`. Measured dead ends (don't repeat): a canvas painted per Card on every mount (deck open 17 s on a phone-speed CPU); encoding faces to webp/png blobs for `<img>` (lossy webp looks softer; PNG/lossless encode is 0.5 s+/card and runs on Safari's main thread → 30 s+ to load); full-res canvases per Card (slow to composite/filter). The matchup splash prewarms your whole deck (`prewarm`, starting hand first, with a progress line) and downloads everyone's card art (`preloadArt`). The painter preloads only frame parts; token/rune/marker/tie-breaker/life art is `::emoji::`-only and loads on demand (`loadImages`). No `{#key}` around a Card — it swaps faces itself without a blank frame.
- **CSS:** `app.postcss` keeps only `@tailwind base` (preflight + Flowbite form resets the look depends on). The app uses NO Tailwind utility classes — everything is scoped Svelte CSS. Don't re-add the components/utilities layers or a safelist (that was 439 KB of CSS; now 13 KB).
- **Don't lazy-load GameView with a plain dynamic `import()`:** tried — with the preview routes importing it statically, the bundler's chunk split made modules evaluate out of order and the game screen crashed (`Cannot read properties of null (reading '$')`). Reverted. If retried, verify the deploy build (move the gitignored `preview-*` routes out) AND a live game.
- adapter-static: the game placeholder was once a catch-all `{:else}` and leaked onto other modes — scope each mode explicitly.
- Screenshot harness pattern (only when needed): build, serve `build/` with a tiny node http server that strips the `/goa2` base and falls back to `<route>.html`, launch Chromium at `executablePath:'/opt/pw-browsers/chromium'`, import playwright by absolute path from `node_modules`. Delete any `preview-*` route after.

- **The map is drawn from the map DATA, not from the official painting** (`images/board/forgotten_island.webp` is only the editor's tracing image — its hexes are irregular, and the user wants custom maps from the editor to look just as good).
- **Island look (`BoardCanvas look="island"`; the GAME uses it by default):** `src/lib/board/hexgeo.ts` (tested; the ONE place for hex maths: centres, corners, neighbours, `outlineLoops` = the outline of any set of hexes as closed loops, `smoothPath`, `borderPath`, `hexHash`/`intHash`). Layers in `.board-wrap` (see "Board layers" below): (1) `board/Ocean.svelte` = one `<canvas>`, drawn in board units through the view matrix (`viewM`): depth gradient, two noise TEXTURES made once (tileable fractal value noise → `CanvasPattern`s: dark swells, and pale broken streaks laid twice at different size/angle/drift so they cross — the earlier drawn arc "crests" looked cartoony and were dropped), shelf bands + breathing foam stroked along the coast path (the user likes these as they are), vignette; 30 draws a second from a timer, paused when hidden, still under "reduce motion" / `seaStill`. (2) `svg.land` holding `board/IslandLayer.svelte` — its OWN svg, with the view applied as a CSS `transform: matrix()` (`landTf`, the same matrix re-expressed in css px) and `will-change: transform` only while the view moves (`moving`, 240 ms): pan/zoom slides one GPU layer instead of re-processing ~5k shapes. Measured dead end: the island inside the pieces svg under the `<g transform>` made pan/zoom 4–5× slower than classic. (3) `svg.pieces` = the old svg (hover hex, areas, pieces, pings) with the attribute transform, so hit-testing is unchanged. IslandLayer (svg namespace, static, no pointer events, no svg filters): coast skirt + shadow, a seam + rounded gradient tile per hex by zone type (three lightness variants by hash), a damp band inside the shore, then `scenery` placed by hash from drawings in `<defs>` (60-unit hex design space): jungle = leaf litter/moss patches, rim growth (palm, bush, fern, broadleaf tree, mushrooms, log, flowers); beach = ripples, shell, starfish, pebbles, driftwood, dry tuft; centre = cracks, pebbles, dry tufts, old paving slabs, shrub; grass + ferns creep onto open ground next to forest; Atlantean base = TECH (copper `plate` seams + rivets on every hex, vent, porthole, gauge, valve, pipe); Titan base = ICE (pale glacier tiles, frost patches, hairline cracks, snow, crystal clumps). Clarity rules: small things small and low-contrast, anything tall on the hex RIM (never the middle), `low` vs `tall` lists (tall casts a shadow via `sr` or a `<ref>-shade` drawing). Hero spawn emblems follow the tie-breaker coin: copper 12-tooth gear on slate, and a five-point star (one-line pentagram `PENTA`) in a ring on red stone — NOT a six-point star (the user asked). Also cracks between zones and the terrain hexes: a BOULDER by default. Scatter terrain is opt-in per hex from the map: `GameMap.scatter` (hex → key; kinds in `board/scatter.ts`: mossy rock, crystals in four colours (drawn UPRIGHT, colours through CSS variables on the `<use>`), giant mushroom, fan plant, toothed plant, dead tree, orb on a stalk, broken pillar, rune stone, carved cube (`RAISED`: a foot, a thick line as the column leaning away from the light, a top kept screen-upright), cooling lava, ice floe), set with the map editor's **Scatter** tool (terrain hexes only; "See it on the island" opens `/map-lab?map=__editor`). The user tried an automatic sprinkling of these and did NOT like it ("return the rocks") — never auto-place scatter; it is the map author's choice. Shadows/highlights use `down` (screen-down in board coords) so the light is right when the board is turned 180°.
- **Minion art (from the user's 3D models):** `tools/minion_art.py` (numpy + pillow) reads `references/GOA2-Plain-Minion-*.stl` (the user's folder, git-ignored: 35 MB of models plus photos of their physical board; Orange H/M/R = heavy/melee/ranged, Blue L/M/S = heavy/melee/ranged) and writes `src/lib/board/minionArt.ts` (GENERATED: six emblems as svg path data, even-odd fill, hex centre 0,0 / corners 100 away, plus `cx cy r`) and the flat sprites `images/minions/*.png` (classic board, editor, the HUD wave icon). The models are flat hex tokens with the art ENGRAVED as grooves: the outlines are the edges used by exactly one top-face triangle, chained into loops (exact vectors). Dead end: sampling the height map → the old speckled line art. `board/MinionDefs.svelte` (inside BoardCanvas's `<defs>`, usable from any svg on the page): `#mn-art-<team>-<role>` (the emblem), `#mn-top-…` (the piece's face + emblem: copper for Atlanteans, ice for Titans), `#mn-rim-…` (dark rim + PIPS: 4 = ranged, 6 = melee, 8 = heavy — the type at any size) and `#mn-token-…` (the whole piece, still: the drag ghost). BoardCanvas draws minion pieces with `<use>` in both looks (the old `images/minion_tokens` PNGs are deleted). The pips TURN — clockwise for Atlanteans, anticlockwise for Titans — which is also what tells a minion from the spawn point it stands on (the user's idea; they rejected a type badge on spawn hexes). Emblems are turned −30° (flat-top model → pointy-top board), the same turn the old sprites had, so `meta.dir` facings in existing maps still hold. Island look: a minion spawn point is a FULL hex of its team's ground (copper deck / ice, whatever zone it is in), the emblem engraved on it facing its `dir` (no badge); no scenery on spawn hexes.
- **Board layers and what may animate (measured with CDP `Performance.getMetrics` → main-thread ms per second; the rAF-interval probe is useless in headless Chrome):** `.board-wrap` stacks ocean `<canvas>` → `svg.land` (static) → `svg.land.zone` (the battle-zone outline, `zoneGlow`) → `div.rims` (one small html element per minion: its rim + pips) → `svg.pieces`. The land, zone and rims layers share one CSS matrix (`landTf`; `fit` = viewBox → css px). RULES learned the hard way: (1) anything that animates must be a `transform` or `opacity` animation on an HTML-level element (a span, or a whole `<svg>` root) so the GPU does it — NOT the `rotate` property (ran on the main thread: 720 ms/s idle), NOT a `<g>` or `<path>` inside a big svg (re-styles and repaints that svg every step). (2) No `requestAnimationFrame` loop for the sea: it is a 30/s `setInterval` — a rAF loop makes the page produce 60+ frames a second and each one re-ticks every running animation (it roughly tripled idle work). Idle now ≈ 27 ms of main-thread work per second with 14 minions turning and the sea moving; classic ≈ 3.
- **Pieces are components in `board/` (svg namespace), shared by BoardCanvas and the token lab:** `PieceDefs` (MinionDefs + the silver shield + the three crests — include once per page inside a `<defs>`), `HeroToken` (dark rim, the PLAYER's colour as the outer band, the team's copper / ice as the inner band, the face filling the middle; radius 0.78 hex), `KitToken` (a hero's own pieces: TOKENS are HEXES that are small copies of the MAP hex they stand on — pointy-topped, corners towards the map hex's corners, and the frame stays LOCKED to the map when the board turns (`rot` = the board's rotation, turning just the frame back inside the counter-rotated piece) while the art inside stays upright; the painted `token_*.png` art is a flat-topped hex of its own, so it is drawn a little larger and clipped to the frame (`uid` = clip id); MARKERS and runes are ROUND; either way the rim is the owner's colour; face-down mine = owner-colour hex + `#crest-skull`; companions: Pyro = `#crest-dragon` (a cute baby dragon), Turret = `#crest-gun` (a mounted machine gun) — the three crests are plain svg files in `board/crests/` (viewBox −50 −50 100 100, shapes only, no ids), inlined as symbols by PieceDefs; they came out of a three-artist / two-judge run, legibility at 44 px being the test), `tokenArt.ts` (`tokenImg`, `isMarkerArt`). ## Performance rules (measured 2026-10-03 — the user: "efficient and fast, that's super important", must run on weak PCs and old browsers)
- Measure with CDP `Performance.getMetrics` (main-thread ms per second) AND a run with `--disable-gpu` (software rendering = a weak PC: there the rAF frame rate is real). Before the fixes: landing 354 ms/s, game 602 ms/s, and 18–20 fps in software on landing / menus / game; after: 11 and 36 ms/s, 60 fps in software.
- **Never animate `filter`, `box-shadow`, `width` / `height` / `top` / `left`, or anything else that paints.** An always-running glow pulse written as a `box-shadow` or `filter` keyframe repaints on the main thread every frame (ONE pulsing button cost 60% of a core in the game; the landing crest's breathing `drop-shadow` cost 35%). A pulse is: a STATIC shadow plus an `opacity` (and/or `transform`) keyframe. Progress bars: `transform: scaleX()`, not `width`.
- **No `backdrop-filter` anywhere** (`--glass-blur` is `none`; panels are nearly opaque instead). A blur over the moving sea was re-blurred on every sea frame. Likewise no `filter` on a container of something animated (the backdrop is dimmed by its scrim, not by a filter). The `reveal` transition is fade + lift only (no blur).
- **The sea canvas is small** (`Ocean.svelte`: about 0.65 megapixels whatever the window or pixel density, stretched by CSS), its shelf strokes are cached in a spare canvas per view, it moves 20 times a second, and redraws at once when the view changes.
- Nothing inside `svg.pieces` animates (the selection ring no longer spins).
